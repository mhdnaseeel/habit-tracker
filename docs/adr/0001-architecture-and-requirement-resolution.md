# ADR-0001: Architecture and PRD conflict resolution

Date: 2026-10-05. Status: accepted. Decider: engineering judgment authorised by the master prompt.

Later product-owner decisions on weekly freezes, navigation, journal, and MCP supersede the corresponding rows below; see ADR-0003.

## Context

Backend §2 allows separate services **or well-defined modules**, and a primary SQL database. The master prompt requires minimal infrastructure. Both PRDs contain conflicting examples and unspecified policies. Decisions below resolve these explicitly; they do not claim missing wireframes or provider credentials exist.

## Decision

Use npm TypeScript workspaces, React/Vite frontend, Fastify API, PostgreSQL persistence and an independently runnable PostgreSQL-backed worker. REST /api/v1 and shared validation contracts. Domain logic is framework-independent. Use PostgreSQL transactions and row locks, not Redis/Kafka or independent domain databases initially. Add capacity infrastructure only after measured need.

## Alternatives

Microservices with Redis/stream/warehouse: independent scaling, but operational cost and transaction complexity unjustified by measured load. SQLite: easy local development, but does not validate PostgreSQL concurrency/constraints. Next.js combined server: fewer deployments, but separate REST backend and reusable domain boundary better match PRD web/mobile requirements.

## Consequences

Simple deployable boundaries and single transactional owner store. Worker throughput and DB query latency must be measured; no claim of 1M-user readiness. Real email/SMS/push/OAuth delivery, encryption at rest, TLS, cloud failover and PITR need infrastructure credentials and deployment verification. Targets (99.9% availability, p95 <200ms, list <1s) are acceptance targets, not established facts.

## Review refinements

Partial numeric habit values contribute to numeric goals even before the daily target is met. Links have effective dates; only activity within link and goal lifetime contributes. Unlink closes the interval without deleting earned progress. Overachievement is retained numerically; displayed percentage caps at 100. Historical correction recomputes progress. Targetless denominator is scheduled habit occurrences within effective link intervals through local today/deadline; empty denominator returns no-data, not 100%.

Keep core history for account lifetime: §11 five-year pruning is an example, not automatic policy. Account erasure cascades personal records; scrub audit actor/identifiers and private payloads. Backups expire under documented retention; a restore must replay erasure records before service resumes. Sync tombstones have bounded retention and older cursors require full resync. Analytics consent/opt-out controls nonessential collection; private transactional insight calculations remain available without external tracking.
