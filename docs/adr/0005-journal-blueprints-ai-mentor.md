# ADR-0005: Journal blueprints, account drafts, and optional AI Mentor

Date: 2026-10-14

The daily journal remains **one entry per account and local calendar date**, consistent with ADR-0004. Migration 008 adds structured responses, a draft/saved state, an optional blueprint reference, and a prompt snapshot. Existing rows retain their content and version and default to `saved`; no existing journal text is rewritten. Migration 009 seeds five system blueprints. The blueprint table can accept later templates without changing the entry schema. System blueprints have no user mutation endpoint.

Drafts are saved to PostgreSQL using the same optimistic version check as finished entries. The browser keeps only the text currently being edited in React memory while a request is pending or offline; there is no separate browser-storage copy. Navigation and sign-out wait for a draft save and stay on the editor if it fails. A reload while offline cannot recover unsent text, so the UI warns before unload. Template changes preserve free-form text and previously entered response keys. An entry's prompt snapshot remains unchanged when the same blueprint is updated in the catalog.

AI Mentor is optional and never participates in a journal, habit, task, or goal write transaction. A user explicitly requests guidance. Habit, task, and goal context is disclosed in the UI. Journal content is excluded unless the account's `ai_journal_consent` setting is enabled; this includes saved drafts. The user may revoke consent. Each request retrieves at most seven journal entries within 14 days and up to 28 days of recorded check-ins. Journal excerpts are truncated to 1,000 characters each. Provider calls use the existing OpenAI Responses integration and server-side key, `store: false`, a response token limit, an 18-second timeout, one retry for server errors, and a per-route rate limit. Guidance is not persisted. Account export includes journal state and consent; account deletion cascades through journal rows and settings.

The model returns structured recommendations with evidence IDs. The API rejects unknown IDs and recommendations without an evidence item from the claimed area. Evidence shown to the user is sourced from application data, not model prose. AI suggestions remain suggestions; they do not change user records. Request summaries and provider errors are logged without journal text or credentials. Provider retention is governed by the provider's policy; `store: false` does not establish zero retention.

This change supersedes ADR-0004's plain-text-only interface while keeping its single-entry rule. The original backend PRD mentions rich-text reflections, but the later product-owner daily-journal requirement and existing plain-text format remain authoritative here. No rich-text editor or separate reflection entity is introduced.
